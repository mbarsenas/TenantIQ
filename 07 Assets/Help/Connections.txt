# TenantIQ - Connecting to Microsoft 365

TenantIQ establishes authenticated, read-oriented administrative sessions to collect evidence for the workload being assessed.

TenantIQ v1.0 supports assessment of:

  Exchange Online
  Entra ID
  SharePoint Online
  Microsoft Teams
  OneDrive
  Microsoft Intune
  Microsoft Defender
  Microsoft Purview

## Connection Model

Start TenantIQ with:

  .\Start-TenantIQ.ps1

Select a workload from the main menu. TenantIQ then prepares the Microsoft administrative interface required by that workload and prompts for authentication when necessary.

Some workloads intentionally run in isolated PowerShell 7 processes. Isolation prevents Microsoft authentication libraries and workload modules from polluting the shared TenantIQ process. Because of this design, a sign-in completed for one workload does not guarantee that another workload will reuse the same authentication context.

Multiple Microsoft sign-in prompts during a complete 1-through-8 assessment can therefore be expected behavior.

TenantIQ does not require administrators to store passwords in TenantIQ configuration files.

## Exchange Online

Exchange Online uses ExchangeOnlineManagement.

Microsoft connection command:

  Connect-ExchangeOnline

Connection information can be inspected with:

  Get-ConnectionInformation

TenantIQ uses isolated execution for Exchange Online assessment so Exchange authentication assemblies remain separate from Microsoft Graph authentication where required.

If Exchange authentication produces Microsoft.Identity.Client, MSAL, WAM, or assembly-manifest errors, close stale PowerShell sessions and verify that the installed ExchangeOnlineManagement version is healthy.

Check installed versions with:

  Get-Module ExchangeOnlineManagement -ListAvailable

## Entra ID / Microsoft Graph

Entra ID evidence is collected through Microsoft Graph PowerShell.

Microsoft connection command:

  Connect-MgGraph

Current Graph context:

  Get-MgContext

TenantIQ requests delegated Graph scopes needed by its registered controls. Administrator consent may be required for some scopes.

A successful Graph sign-in does not guarantee that every control can retrieve its evidence. Licensing, Graph API availability, tenant configuration, role assignments, and consent can still affect individual controls.

## SharePoint Online

SharePoint Online uses the SharePoint Online Management Shell and the tenant administrative endpoint.

Typical Microsoft connection command:

  Connect-SPOService -Url https://<tenant>-admin.sharepoint.com

When TenantIQ requests the SharePoint tenant name, enter either the tenant prefix or the onmicrosoft.com tenant name as requested by the prompt.

Example tenant:

  contoso.onmicrosoft.com

Some SharePoint evidence can require site-level administrative access in addition to tenant-level SharePoint administration. TenantIQ reports unavailable evidence rather than assuming inaccessible configuration is healthy.

## Microsoft Teams

Microsoft Teams assessment uses the MicrosoftTeams PowerShell module together with Microsoft Graph evidence where required by individual controls.

The Microsoft Teams module must be installed before TenantIQ starts:

  Install-Module MicrosoftTeams -Scope CurrentUser

Complete Microsoft authentication when TenantIQ launches the Teams assessment. Permissions and tenant licensing determine which Teams configuration objects can be evaluated.

## OneDrive

OneDrive for Business is built on SharePoint Online infrastructure. TenantIQ therefore uses SharePoint administrative connectivity and Microsoft Graph evidence where required for OneDrive controls.

TenantIQ may request the SharePoint tenant name before running OneDrive assessment.

The administrative endpoint follows the same format:

  https://<tenant>-admin.sharepoint.com

OneDrive evidence availability can depend on SharePoint administrative access, Graph permissions, licensing, and whether OneDrive resources have been provisioned in the tenant.

## Microsoft Intune

Microsoft Intune assessment primarily uses Microsoft Graph.

TenantIQ prepares the required Graph authentication context and requests access appropriate to its Intune evidence collection.

Evidence availability depends on Intune licensing, Graph permissions, administrator consent, and whether the corresponding Intune feature is configured in the tenant.

A tenant with no managed devices or no configured policy of a particular type can legitimately produce informational or warning findings; that does not indicate an authentication failure.

## Microsoft Defender

Microsoft Defender assessment can require both Exchange Online security-policy cmdlets and Microsoft Graph evidence.

TenantIQ runs Defender in an isolated PowerShell process so Exchange Online policy cmdlets can be loaded without contaminating the shared Graph/MSAL session.

During Defender assessment, TenantIQ may launch an Exchange Online sign-in specifically for Defender policy checks and separately establish Graph evidence collection. These prompts are expected when the isolated process does not already have the required authentication context.

## Microsoft Purview

Microsoft Purview assessment uses Microsoft compliance/security administrative capabilities exposed through supported Microsoft PowerShell interfaces.

Some Purview evidence depends on which compliance cmdlets Microsoft exposes in the active session, tenant licensing, roles, and service-side availability.

If a supported evidence source is unavailable, TenantIQ can return NOT EVALUATED or INFO rather than fabricating a scored result. For example, an audit-search readiness control may be unscored when no supported Purview audit-search cmdlet is available in the session.

## MFA and Conditional Access

TenantIQ uses Microsoft's interactive authentication mechanisms and supports accounts protected by MFA.

TenantIQ does not bypass Conditional Access. The administrative account and workstation must satisfy organizational requirements such as:

  MFA
  Authentication strength
  Compliant or managed device
  Trusted location
  Approved client requirements

If Microsoft rejects authentication because of Conditional Access, resolve the Microsoft access requirement rather than weakening the policy for TenantIQ.

## Multiple Tenants

Always verify the tenant used during Microsoft authentication before running an assessment. This is especially important for consultants and administrators who manage multiple Microsoft 365 tenants.

Workload CSV files and the Portfolio Report represent the tenant from which their source evidence was collected. Do not combine assessment files from different customer tenants into one portfolio report.

## Manual Connection Diagnostics

When troubleshooting, these Microsoft commands can help determine whether the underlying Microsoft module can authenticate independently of TenantIQ.

Exchange Online:

  Connect-ExchangeOnline
  Get-ConnectionInformation

Microsoft Graph:

  Connect-MgGraph
  Get-MgContext

SharePoint Online:

  Connect-SPOService -Url https://<tenant>-admin.sharepoint.com
  Get-SPOTenant

Teams:

  Connect-MicrosoftTeams

If the Microsoft connection command itself fails, resolve the module, network, account, consent, Conditional Access, or Microsoft service problem before treating it as a TenantIQ assessment-engine defect.

## Troubleshooting Authentication

Check, in order:

  1. Run TenantIQ from PowerShell 7.
  2. Confirm .\Start-TenantIQ.ps1 reports all required dependencies as [OK].
  3. Verify Internet and DNS connectivity.
  4. Complete all Microsoft MFA and Conditional Access prompts.
  5. Verify the correct tenant and administrator account were selected.
  6. Verify required administrator roles and Graph consent.
  7. Check tenant licensing for the evidence being queried.
  8. Check Microsoft service/API availability.
  9. For Exchange/MSAL assembly problems, close stale PowerShell processes and inspect installed ExchangeOnlineManagement versions.
  10. Re-run only the affected workload after correcting the underlying condition.

## Security

Do not place passwords, access tokens, client secrets, refresh tokens, private keys, or other credentials in the TenantIQ repository, scripts, reports, or documentation.

TenantIQ delegates interactive authentication to Microsoft's supported administrative modules and identity platform.
