# TenantIQ - Getting Started

Welcome to TenantIQ.

TenantIQ is a read-only Microsoft 365 assessment platform designed to evaluate configuration, security, governance, and operational posture across supported Microsoft 365 workloads. TenantIQ collects evidence, evaluates controls, and produces standardized findings and customer-facing reports. It does not automatically remediate or change tenant configuration.

## Starting TenantIQ

TenantIQ requires PowerShell 7 or later.

Open PowerShell 7 and navigate to the TenantIQ installation directory. Start the product with:

  .\Start-TenantIQ.ps1

Start-TenantIQ.ps1 is the supported product entry point. It validates the environment and required PowerShell dependencies before opening the TenantIQ main menu.

Do not use TenantIQ.ps1 as the normal product launch command.

## Startup Validation

At startup, TenantIQ checks the local environment for required components. Required dependencies must be available before the main menu launches.

The startup screen reports each dependency as OK, MISSING, or OPTIONAL. Optional components do not prevent TenantIQ from starting, but controls that depend on unavailable optional capabilities may be returned as unscored informational results.

## Authentication

TenantIQ uses Microsoft-supported administrative PowerShell and Microsoft Graph authentication for evidence collection. Depending on the selected workload, a Microsoft sign-in window may appear.

Authentication and available evidence can vary based on tenant licensing, administrator permissions, Microsoft API availability, and workload-specific PowerShell capabilities.

TenantIQ is designed for assessment and reporting. Authentication is used to read supported tenant configuration and evidence; TenantIQ does not automatically apply remediation actions.

See "Connecting to Microsoft 365" in the Help Center for additional details.

## Running an Assessment

From the main menu:

  1. Select the workload.
  2. Complete Microsoft authentication if prompted.
  3. Allow all registered checks to finish.
  4. Review the assessment summary.
  5. Locate the generated CSV in the 06 Output directory.

Each result is standardized with fields such as workload, check, category, status, severity, finding, evidence, and recommendation where available.

## Understanding Statuses

PASS
  The evaluated condition met the TenantIQ control criteria.

WARNING
  The control detected a condition that should be reviewed or improved but is not classified as a failure.

FAIL
  The evaluated condition failed the TenantIQ control criteria and should receive remediation attention.

INFO
  Contextual or informational evidence. INFO results are not included in scored-control posture calculations.

NOT EVALUATED
  The control could not be conclusively evaluated, commonly because a required API, cmdlet, permission, license, or evidence source was unavailable. Portfolio reporting treats these results as unscored context rather than silently dropping them.

A FAIL does not mean TenantIQ itself failed to run. FAIL can represent a legitimate tenant configuration finding. Runtime or authentication errors are reported separately during execution.

## Portfolio Report

After workload assessments are complete, select:

  [9] Portfolio Report

TenantIQ reads the latest available workload CSV for each supported workload and generates:

  TenantIQ-Portfolio-Assessment-<timestamp>.html
  TenantIQ-Portfolio-Assessment-<timestamp>.csv

The executive HTML report includes:

  Portfolio posture score
  Workload coverage
  Assessment snapshot
  Per-workload posture
  Priority FAIL and WARNING findings
  Recommended next steps

Scoring uses:

  PASS    = full credit
  WARNING = half credit
  FAIL    = no credit
  INFO / NOT EVALUATED = unscored context

Portfolio posture labels are:

  90-100  Strong Posture
  75-89   Needs Attention
  60-74   Elevated Risk
  0-59    High Risk

Individual FAIL findings remain visible and prioritized regardless of the overall portfolio score.

## Output Directory

Assessment and portfolio output is written under:

  06 Output

Keep workload CSV files if you want them represented in a later Portfolio Report. The portfolio report selects the latest available CSV for each workload.

## Recommended First Full Assessment

For a new tenant assessment:

  1. Start TenantIQ with .\Start-TenantIQ.ps1.
  2. Confirm the startup prerequisite validation passes.
  3. Run workloads 1 through 8.
  4. Complete authentication when prompted.
  5. Confirm each workload exports its assessment CSV.
  6. Select 9 to generate the Portfolio Report.
  7. Review FAIL findings first, followed by high-severity WARNING findings.
  8. Validate recommendations against tenant requirements before making production changes.
  9. Re-run affected workloads after remediation to document posture improvement.

## Important

TenantIQ findings are assessment guidance, not automatic change instructions. Tenant configuration, licensing, business requirements, exceptions, and Microsoft service behavior should be considered before remediation.

For production use, review findings with a qualified Microsoft 365 administrator or security professional before changing tenant configuration.
