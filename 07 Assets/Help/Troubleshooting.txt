# TenantIQ - Troubleshooting

Use this guide when TenantIQ fails to start, authenticate, execute a workload, or generate expected output.

## 1. Start With the Supported Launcher

Run TenantIQ from PowerShell 7 with:

  .\Start-TenantIQ.ps1

Do not use TenantIQ.ps1 as the normal product entry point.

The startup validator must report all required dependencies as [OK] before the assessment engine loads.

## 2. PowerShell Runtime

TenantIQ v1.0 requires PowerShell 7 or later.

Check:

  $PSVersionTable.PSVersion

If pwsh.exe is unavailable, install PowerShell 7 before troubleshooting workload behavior.

## 3. Missing Modules

Start-TenantIQ.ps1 prints required missing dependencies and the corresponding Install-Module command.

Common required modules include ExchangeOnlineManagement, Microsoft Graph modules, Microsoft.Online.SharePoint.PowerShell, and MicrosoftTeams.

After installing or changing modules, close old PowerShell sessions and start a fresh PowerShell 7 process.

## 4. Authentication Prompts

Multiple sign-in prompts can be expected during a full 1-through-8 assessment because some workloads intentionally run in isolated PowerShell processes.

Do not assume a new prompt means the previous workload failed.

Verify the correct Microsoft 365 tenant and administrative account each time authentication is requested.

## 5. Exchange Online / MSAL Errors

Symptoms can include:

  Could not load Microsoft.Identity.Client.dll
  Manifest definition does not match assembly reference
  WAM or MSAL authentication errors
  Exchange cmdlets not available after Graph authentication

TenantIQ isolates Exchange-dependent workloads to reduce these conflicts.

If the problem persists:

  1. Close all stale PowerShell sessions.
  2. Open a fresh PowerShell 7 window.
  3. Check installed ExchangeOnlineManagement versions:

       Get-Module ExchangeOnlineManagement -ListAvailable

  4. Verify Connect-ExchangeOnline works independently.
  5. Rerun only the affected TenantIQ workload.

## 6. Microsoft Graph Problems

Check Graph authentication with:

  Get-MgContext

If no context exists, test:

  Connect-MgGraph

A successful sign-in does not guarantee every control has access to its evidence. Review administrator consent, Graph scopes, tenant roles, licensing, and API availability.

## 7. SharePoint / OneDrive Connection Problems

Typical symptoms:

  No valid OAuth 2.0 authentication session exists
  Connect-SPOService fails
  Get-SPOTenant fails

Verify the SharePoint administrative endpoint and test outside TenantIQ:

  Connect-SPOService -Url https://<tenant>-admin.sharepoint.com
  Get-SPOTenant

Run TenantIQ again only after the Microsoft SharePoint command succeeds.

## 8. Teams Problems

Verify MicrosoftTeams is installed and test:

  Connect-MicrosoftTeams

Permissions, licensing, and service-side API behavior can limit individual Teams controls even after authentication succeeds.

## 9. Intune Results With No Devices

A tenant with zero managed devices can legitimately return informational results. Zero inventory should not automatically be interpreted as healthy posture for device-specific controls.

Review Finding and Evidence before interpreting PASS, WARNING, INFO, or NOT EVALUATED.

## 10. Defender Policy Cmdlets Missing

Defender assessment can require Exchange Online protection-policy cmdlets such as anti-phishing, Safe Links, Safe Attachments, anti-spam, and malware policy commands.

TenantIQ runs Defender in an isolated process and loads Exchange Online policy capabilities before Graph evidence collection.

If those cmdlets remain unavailable, verify ExchangeOnlineManagement authentication independently before changing Defender assessment logic.

## 11. Purview Evidence Not Available

Some Purview controls depend on Microsoft compliance cmdlets exposed in the active session.

A result such as NOT EVALUATED can be legitimate when Microsoft does not expose a supported evidence source. Review the Finding field for the exact limitation.

Do not manually convert unavailable evidence to PASS.

## 12. Missing Function Errors

Examples:

  Start-TenantIQ<Workload>Assessment is not recognized
  Show-TenantIQAssessmentResults is not recognized

These indicate a runtime/framework loading problem rather than a tenant finding.

Confirm the local repository is current:

  git pull

Then start a fresh PowerShell 7 session and rerun .\Start-TenantIQ.ps1.

## 13. Parameter Prompts That Should Not Appear

If an internal helper unexpectedly prompts for a parameter such as OutputPath, an executable helper may have been loaded as if it were a library script.

This is a TenantIQ runtime defect. Capture the exact prompt and workload path; do not enter arbitrary values to force the assessment forward.

## 14. Report Count Mismatch

Portfolio totals should reconcile across PASS, WARNING, FAIL, and unscored context.

TenantIQ treats statuses outside PASS/WARNING/FAIL as unscored context in portfolio aggregation so INFO, NOT EVALUATED, blank, or legacy unscored statuses are not silently dropped.

If totals do not reconcile, confirm you pulled the current version and regenerate option [9].

## 15. Portfolio Report Uses Old Data

The Portfolio Report selects the latest available workload CSV for each supported workload.

If a workload row appears stale:

  1. Confirm the newer workload CSV exists under 06 Output.
  2. Confirm its filename follows the TenantIQ workload assessment pattern.
  3. Regenerate option [9].

Do not mix output from different customer tenants.

## 16. Distinguishing Findings From Runtime Errors

A standardized FAIL with Finding and Recommendation normally represents a tenant posture finding.

A red console exception, missing cmdlet, missing function, authentication termination, or workload process exit code represents a runtime or connectivity problem.

Treat these differently during troubleshooting.

## 17. Recommended Troubleshooting Order

  1. Confirm PowerShell 7.
  2. Run .\Start-TenantIQ.ps1 and verify prerequisites.
  3. Pull the latest repository changes.
  4. Reproduce only the affected workload.
  5. Test the underlying Microsoft connection command independently.
  6. Verify tenant, account, licensing, roles, scopes, and consent.
  7. Close stale PowerShell processes after module/authentication changes.
  8. Preserve the console error and generated CSV for diagnosis.

## 18. Protecting the Validated Baseline

The validated TenantIQ v1.0 assessment baseline is preserved in GitHub on:

  baseline/tenantiq-v1.0-validated

Do not modify the validated assessment modules simply to work around an environment, permission, licensing, or Microsoft API limitation. First prove that the assessment engine itself has regressed.
