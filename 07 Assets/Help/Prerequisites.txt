# TenantIQ - Prerequisites

Before running TenantIQ, verify that the workstation and Microsoft 365 administrative account meet the following requirements.

## Operating System

TenantIQ is currently designed to run from a Windows administrative workstation.

Recommended environment:

  Windows 10 or Windows 11
  Windows Server administrative workstation
  64-bit operating system

TenantIQ relies on Microsoft PowerShell modules used to administer Microsoft 365 services.


## PowerShell

TenantIQ requires Windows PowerShell or a compatible PowerShell environment capable of loading the Microsoft 365 administrative modules required by each workload.

For the current TenantIQ release, Windows PowerShell 5.1 is recommended.

Check your PowerShell version with:

  $PSVersionTable.PSVersion

TIP: Use a dedicated PowerShell session for TenantIQ to reduce the possibility of module or authentication-library conflicts.


## PowerShell Execution Policy

PowerShell must permit TenantIQ scripts to execute.

Check the current execution policy with:

  Get-ExecutionPolicy -List

If scripts are blocked, consult your organization's PowerShell security policy before changing the execution policy.

WARNING: Do not weaken organizational PowerShell security controls simply to run TenantIQ.


## Required Microsoft 365 Modules

TenantIQ uses Microsoft administrative PowerShell modules to retrieve Microsoft 365 configuration information.

The modules required depend on the workload being assessed.


## Exchange Online

Exchange Online assessments require:

  ExchangeOnlineManagement

Check whether the module is installed:

  Get-Module ExchangeOnlineManagement -ListAvailable

Install it when necessary:

  Install-Module ExchangeOnlineManagement -Scope CurrentUser

TenantIQ uses Exchange Online PowerShell to retrieve messaging, mail flow, security, authentication, and tenant configuration information.

TIP: Avoid keeping obsolete versions of ExchangeOnlineManagement installed when they are no longer required. Conflicting module or authentication-library versions can cause connection problems.


## Entra ID

Entra ID assessments use Microsoft Graph PowerShell.

The required Microsoft Graph modules depend on the TenantIQ health checks being executed.

Check installed Microsoft Graph modules with:

  Get-Module Microsoft.Graph* -ListAvailable

Microsoft Graph PowerShell can be installed with:

  Install-Module Microsoft.Graph -Scope CurrentUser

TenantIQ may request Microsoft Graph permissions required to read the configuration being assessed.


## SharePoint Online

SharePoint Online assessments require the SharePoint Online Management Shell module.

The module provides commands such as:

  Connect-SPOService
  Get-SPOTenant
  Get-SPOSite
  Get-SPOUser

Check whether the module is installed:

  Get-Module Microsoft.Online.SharePoint.PowerShell -ListAvailable

If required, install the SharePoint Online Management Shell before running SharePoint Online assessments.


## Administrative Permissions

TenantIQ is designed for Microsoft 365 administrators and requires sufficient read access to the configuration being assessed.

Required permissions vary by workload and by individual health check.

An account may successfully connect to a service but still lack permission to retrieve specific configuration information.

When this occurs, TenantIQ may report that the health check could not be completed or that specific objects could not be evaluated.


## Exchange Online Permissions

The administrative account must have sufficient Exchange Online permissions to retrieve the configuration evaluated by TenantIQ.

Some checks may require elevated Exchange administrative roles depending on the configuration being queried.


## Entra ID Permissions

Entra ID assessments use Microsoft Graph permissions.

The scopes required depend on the health checks being executed.

TenantIQ should request only the permissions necessary to retrieve the Microsoft Graph configuration required for assessment.

Some Microsoft Graph permissions may require administrator consent.


## SharePoint Online Permissions

SharePoint Online assessments generally require SharePoint administrative permissions.

Some site-level operations have additional requirements.

For example, retrieving site users or site collection administrators may require the connected account to have appropriate administrative access to the individual site.

A SharePoint Administrator connection alone does not guarantee that every site-level object can be enumerated.

TenantIQ should identify sites that cannot be evaluated rather than automatically treating inaccessible sites as unhealthy.


## Authentication

TenantIQ uses Microsoft's supported authentication mechanisms provided by the administrative PowerShell modules.

Interactive authentication may be required when a connection does not already exist.

Multi-factor authentication is supported through the Microsoft authentication process used by the applicable module.

TenantIQ should never require an administrator's Microsoft 365 password to be stored in TenantIQ configuration files.


## Internet Connectivity

The workstation running TenantIQ requires network access to the Microsoft 365 services being assessed.

This may include Microsoft authentication endpoints and administrative service endpoints for:

  Exchange Online
  Microsoft Graph
  SharePoint Online

Corporate firewalls, proxies, SSL inspection, Conditional Access policies, or endpoint security controls may affect connectivity.


## Tenant Connectivity

Before running assessments, TenantIQ must establish or detect an authenticated connection to the selected workload.

Typical Microsoft administrative connection commands include:

Exchange Online:

  Connect-ExchangeOnline

Entra ID / Microsoft Graph:

  Connect-MgGraph

SharePoint Online:

  Connect-SPOService -Url https://<tenant>-admin.sharepoint.com

TenantIQ may automatically detect or initiate these connections where supported.

See "Connecting to Microsoft 365" in the Help Center for additional information.


## Required TenantIQ Files

Do not remove or rename TenantIQ framework, module, health-check, or asset directories unless the TenantIQ configuration has also been updated.

The TenantIQ installation contains components such as:

  Framework files
  Health check scripts
  Workload modules
  Configuration files
  Assets
  Help documentation
  Reporting components

Moving individual files without updating their references may prevent health checks or reports from loading.


## Recommended Administrative Workstation

For consistent assessment results, use a trusted administrative workstation with:

  Current Windows updates
  Current Microsoft 365 PowerShell modules
  Reliable Internet connectivity
  Appropriate Microsoft 365 administrative access
  PowerShell script execution permitted by organizational policy

Avoid running TenantIQ from an untrusted or shared workstation.


## Before Your First Assessment

Verify the following:

  1. TenantIQ starts successfully.

  2. Required Microsoft 365 PowerShell modules are installed.

  3. Your administrative account can authenticate.

  4. MFA or Conditional Access requirements can be completed.

  5. The selected workload reports a successful connection.

  6. Individual health checks can retrieve tenant information.

  7. TenantIQ can write to its required local log and report locations.

TIP: Run several individual health checks before the first Full Assessment. This provides a quick way to identify missing modules, permissions, or connectivity problems.
